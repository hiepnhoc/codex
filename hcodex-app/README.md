# codex-ide

Personal desktop IDE built on top of the hcodex harness (`hcodex app-server`,
fork of openai/codex — see `~/github/codex` branch `my-harness` / HCODEX.md).
Tauri 2 (Rust) + React/TypeScript.

```
codex-ide/
├── src-tauri/src/lib.rs   spawns `hcodex app-server`, bridges JSONL <-> webview events
├── src/lib/rpc.ts         JSON-RPC 2.0 client (requests, notifications, server->client requests)
├── src/protocol/          TS types generated by `hcodex app-server generate-ts`
├── src/lib/transport.ts   Tauri bridge in the app, WebSocket in a plain browser (UI dev)
├── src/lib/store.ts       per-thread state: main thread + sub-agents, items, status, approvals
├── src/lib/models.ts      model catalog across every configured provider
└── src/components/        Sessions, AgentTree, AgentPanel, ModelPicker, Editor, FileTree, Terminal
```

## Prerequisites

- `hcodex` installed (`~/.cargo/bin/hcodex`, see HCODEX.md in the codex repo).
- Responses API proxy running at `http://127.0.0.1:8181/v1` (hcodex's default
  `local-proxy` provider); no login or API key needed.
- Node 22 + pnpm, Rust stable.

## Run

```bash
pnpm install
pnpm tauri dev
```

Env overrides read by the Rust side:

| var            | default                                                              |
|----------------|----------------------------------------------------------------------|
| `CODEX_BIN`    | `~/.cargo/bin/hcodex`, else `.../codex-rs/target/release/hcodex`     |
| `CODEX_HOME`   | `~/.hcodex` if it exists, else the binary's default                  |
| `CODEX_IDE_CWD`| current dir                                                          |

## Regenerate protocol types

After every upstream sync / hcodex rebuild:

```bash
hcodex app-server generate-ts --out src/protocol
pnpm exec tsc --noEmit   # catch API drift
```

## UI development in a browser

The desktop shell is not needed to work on the UI. app-server refuses WebSocket handshakes
that carry an `Origin` header, so the dev server proxies `/codex-ws` for its own page only:

```bash
hcodex app-server --listen ws://127.0.0.1:4599
CODEX_IDE_WS=ws://127.0.0.1:4599 pnpm dev
# open http://localhost:1420/?cwd=/path/to/workspace
```

Without `CODEX_IDE_WS` the proxy is off, which is the case for `pnpm tauri dev` and builds.

## Notes from the hcodex side

- `thread/list` hides sessions recorded on other providers unless `modelProviders: []` is sent.
- `modelProvider/list` omits hcodex's built-in `local-proxy` and reports `openai` as the
  default; the picker therefore asks `model/list` without a provider for the default group.
- Sub-agents are not announced by `thread/started`; they arrive as `subAgentActivity` items
  of the parent and as events tagged with their own `threadId`.
